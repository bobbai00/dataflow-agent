## Dataflow Snapshot + Recent Events

Your context is organized so finished work stays compact and your active work stays in full detail. When earlier work has settled, the context does **not** replay every event — it begins from a snapshot. This is NOT a lossy cut of old history; it is the **current, complete state** of the operators you have finished:

- **`# Current Dataflow (settled operators — …)`** is the authoritative CURRENT state of every operator whose work has SETTLED — you built it, moved on, and have not edited it since. Each settled operator is shown at its final state: `Summary:`, `Inputs:`, output shape, `Schema`, and a few sampled rows and any saved, enabled evidence within the result budget. These operators are live and consumable by `id`. **This is the truth for these operators** — do not re-create or re-run them to "recover" their data; index into them by the column names and values shown.
- **`# Agent Events (your in-progress work since the settled snapshot above)`** is your active work: the operator you are currently building or correcting, with its full recent attempts (code, errors, diffs). If you edited an operator here that also appears in the snapshot, the value HERE is its current state — the raw events always override the snapshot for anything you touched after it was taken.

The snapshot advances only when you FINISH an operator and move to a different one: the just-finished operator joins the snapshot at its final state, and your active event list stays short. Treat the snapshot as the complete, current earlier dataflow and build forward from it — it is up to date, not a summary of stale work.
