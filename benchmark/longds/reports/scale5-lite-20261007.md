# Five Lite sessions, Python and dataflow, Luna and Terra, 2026-10-07

## Verdict

With Python's caching fixed, the two arms tie on Terra and Python leads on
Luna. Python is cheaper with both models.

| 5 sessions, 185 questions, one rep | Correct | Cost | Calls per question | Input per call | Cached |
|---|---:|---:|---:|---:|---:|
| Terra, dataflow | 101 (55%) | $10.30 | 3.5 | 31,371 | 94% |
| Terra, Python | 100 (54%) | $8.72 | 4.2 | 21,976 | 95% |
| Luna, dataflow | 47 (25%) | $1.35 | 4.5 | 30,835 | 94% |
| Luna, Python | 57 (31%) | $1.07 | 4.9 | 23,201 | 94% |

The totals are decided by whole sessions that collapse after an early
mistake. One rep cannot separate the arms on Terra, and Luna's 10-question
gap comes from two dataflow collapses that started at question 1.

| Session (questions) | Luna Python | Luna dataflow | Terra Python | Terra dataflow |
|---|---:|---:|---:|---:|
| Kiva crowdfunding, task 1 (37) | 14 | 3 | 31 | 23 |
| Netflix, task 2 (34) | 14 | 3 | 12 | 10 |
| NFL Big Data Bowl, task 1 (42) | 3 | 16 | 32 | 29 |
| Marmara earthquakes, task 1 (36) | 17 | 16 | 16 | 23 |
| WiDS datathon II, task 3 (36) | 9 | 9 | 9 | 16 |

Sessions were chosen for many state-change questions (Update, Counterfactual,
Rollback) and small enough data; Big Data Derby, March Madness and
LearnPlatform (0.6 to 3.9 GB) were left out.

Almost every question depends on earlier ones (180 of 185). Accuracy by
whether the questions it depends on were answered correctly by the same arm:

| | No dependency | All dependencies right | A dependency wrong |
|---|---:|---:|---:|
| Terra, dataflow | 5 of 5 | 37 of 48 (77%) | 59 of 132 (45%) |
| Terra, Python | 4 of 5 | 50 of 62 (81%) | 46 of 118 (39%) |
| Luna, dataflow | 2 of 5 | 6 of 12 (50%) | 39 of 168 (23%) |
| Luna, Python | 2 of 5 | 12 of 19 (63%) | 43 of 161 (27%) |

The collapses start early. Luna's dataflow Kiva session picked
Colombia/Agriculture instead of Vietnam/Agriculture at question 1 and got 3
of 37; its Netflix session's question-1 scores were slightly off and it got
3 of 34. Luna's Python sessions also missed question 1 on both, but only by
format: a missing field and a rounding slip on Kiva, a rounding slip on
Netflix (96.857 for 96.856); the following questions came out right. Luna's Python NFL session went the other way: a slightly wrong
speed signal at question 2 carried through 42 questions (3 correct).

## Cost

| Terra | Fresh input | Cached input | Output | Total |
|---|---:|---:|---:|---:|
| Dataflow | $2.41 (1.21M) | $3.81 (19.0M) | $4.08 (340k) | $10.30 |
| Python | $1.79 (0.90M) | $3.22 (16.1M) | $3.70 (309k) | $8.72 |

Dataflow makes fewer calls (3.5 per question against 4.2) but each carries
more input. Most of the gap is the fixed prompt: a dataflow session's first
call is about 8,800 tokens larger (9,810 against 1,046 on Marmara), which
over 645 calls is about $1.2 of the $1.58 difference. Dataflow also writes
10% more output per question.

## Python baseline fixes in this run

- **Caching.** Each earlier request now stays in place with its entry after
  it, so a task's first call extends the previous one; first calls went
  from 0% to 94-95% cached (488f0f817). Python calls now use the same
  gateway as the dataflow service; the old one's key was inactive.
- **Observer storage.** The Python observer rewrote every table after every
  question (about 1 GB per question on Kiva) and filled the disk 17
  questions into Kiva; unchanged tables are now stored once (510f12830).
- **Kiva timeouts.** The script catalog fingerprinted every table five
  times around each script, and Luna's tables with list cells fell back to
  `repr(to_dict())`, so a 727-row sort ran past the 240 s limit; the
  restart then wiped the catalog and every later call failed. Fingerprints
  are now computed once with a pickle fallback, reads are found by scanning
  code instead of tracing opcodes, and a restarted kernel re-runs the
  session's scripts (c95795626, 472390711). Both Kiva Python sessions were
  rerun from question 1 on this harness, in their own frozen roots; the
  other eight Python sessions had no timeouts and keep their results.
- **Judging.** One verdict was lost while the disk was full (Netflix,
  Terra Python, question 11); it was judged afterwards.
