Interpretation and comparable metrics:
- Three selected tasks per benchmark/model, one first attempt per format; 36 runs, 18 pairs. No benchmark-wide or statistical claim.
- Original official graders and answer parsers unchanged. Full-score >=1 is a derived count; original mean is retained.
- JSON combines typed operators, ordinary callbacks, automatic reads, answer shapes and ordered-call support. This is not an isolated envelope ablation.
- Expression requests provider strict=true; JSON requests strict=false uniformly and retains full local Ajv validation. Provider grammar enforcement is not inferred.
- Unknown timeout billing remains null. Known subtotals are separate. Reasoning is included in output; cached tokens are included in input.
- Provider-reported charges and registry token estimates are distinct. Solving, compatibility/setup and grading costs are separate.
- JSON-only compatibility checks primed some candidate prefixes. Observed warm-cache savings are not an equal cold-start comparison.
- CPU total is cgroup scheduler-runtime seconds. User/system are independent tick counters, not an exact partition.
- Memory is per-attempt kernel-charged peak including persistent native baseline and page cache. Sampled RSS has a different scope. Gateway stays separate; peaks are never summed.
- Task wall includes supervised setup, solve, capture and cleanup. Remote provider CPU/memory is unobserved.
- engine_invocations is the historical field for executeWorkflowAndPersist helper invocations. Backend history records are a separate unit.
- Original240 smol comparisons are historical context: native180s absolute versus script240s network-inactivity policies and persistent native versus fresh script scopes differ.
- No default-format change; expression remains default and JSON is experimental. No automated retries or enlarged follow-up cohort.

Cleanup and experimental plan:
- Cleanup 1: unify operator discriminated types, schema builders and decoding; remove broad any types at validated boundaries and document neutral defaults once.
- Cleanup 2: separate call preparation, atomic graph planning and action execution from the 3704-line agent coordinator; retain one graph engine and explicit failure/order receipts.
- Cleanup 3: give branch-specific schema errors; expose meaningful reader cross-field constraints and worksheet/header metadata. Avoid adding another broad prompt manual.
- Cleanup 4: consolidate accounting around the durable request ledger; preserve raw usage, normalized classes, coverage, source/route/deadline hashes, local ownership and unknown charges.
- Cleanup 5: distinguish helper calls, backend execution records, operator outcomes and requested actions; keep CPU and memory scopes/units explicit.
- Experiment 1: quantify schema overhead separately from prose trimming. Compare a compact optional-neutral-parameter schema with this frozen full schema, keeping local validation and real runtime semantics.
- Experiment 2: separately test worksheet/header discovery, informative raw preview, short batching guidance and final-answer shape. Preserve grouping grain, full-population and formula checks.
- Experiment 3: use small fixed paired tasks before held-out replication, retaining failures and no answer repairs. Treat timeout differences and same-value answer presentation as separate mechanisms.
- Experiment 4: add fresh script/smolagents controls with identical absolute deadlines, retries, input visibility, output limits, routes, shared principles and recorded cache-start exposure. Keep architecture footprints and warm baselines visible.
- Adoption gate: replicated official accuracy gains with acceptable provider-reported charges, token estimates, token classes, CPU, memory and wall time. A two-percent warm-cache estimate difference is insufficient to change defaults.
