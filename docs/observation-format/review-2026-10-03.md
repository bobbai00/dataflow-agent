# Review of the observation-format implementation (2026-10-03)

Review of the uncommitted implementation on top of `3dfbf44b7` and of
[validation.md](validation.md). Read-only: nothing was changed. "Verified"
means checked directly in the rendered files or the code; "reproduced" means a
probe or test run showed it; "from code" means read from the code only.

## Blockers

1. **The default system prompt is cut off inside an open code fence.**
   Verified. `native-mode/SYSTEM_PROMPT.txt` (17 fences) and
   `SYSTEM_PROMPT_WITH_STATE.txt` (27 fences) end with `The retrieved result
   is:` followed by an unclosed text fence. Every native agent with the default
   views (`sample_stats`, `full`) and no flow statistics gets this prompt,
   including all three gold-prefix arms. Cause: the end of example 1 and all of
   example 2 sit at the top of `prompts/native-flow-examples.md` instead of in
   `native-data-examples.md`; the split was made at the receipt line
   `### 3. retrieve summary: ok` inside a fence. Only the data-plus-flow
   combination renders whole, and it is the only combination the tests, the
   live checker and the Luna arms use. The data-only `.replace()` calls in
   `prompts.ts:309-313` never match.
2. **`execute` fails whenever `flowEvidence` is on and `sample` is not an
   offered view.** Verified in code, reproduced by a probe.
   `dataflow-action-runtime.ts:473` builds the flow lines with
   `retrievalOptions(settings, "sample")`, which throws when `sample` is not in
   `retrievalViews`; the default is `["sample_stats", "full"]`. After the engine
   has run, the receipt becomes `execute: error` (`ACTION_FAILED: Retrieve view
   "sample" is unavailable`) and later actions are skipped. KramaBench's flow
   arms set `flowEvidence` without `retrievalViews`.
3. **Complete tables in `sample` and `sample_stats` print their rows out of
   order.** Verified in code (`observation-format.ts:256-259`). Outside `full`,
   rows are always interleaved first, last, second, second-to-last, even when
   every row fits and the caption says `(complete)`. The old renderer printed a
   complete table in stored order. A sorted top-k read this way gives the wrong
   order. Seen in the real LongDS trace (turn 11) and the KramaBench trace.

## Correctness and information

4. **The prompt changes at the second request.** Verified in code. The native
   prompt is rebuilt on every user message (`texera-agent.ts:1982`), and
   `multiTask` turns itself on when a second request arrives
   (`texera-agent.ts:589-592`). The multi-task section (about 2.5k characters)
   then appears in the system prompt, which invalidates the entire cached
   prefix once per session, and task 1 ran under different instructions.
   Decide the section at session start instead.
5. **Context descriptions for `versioned` and `session` were removed.** From
   code. Arms using those layouts (for example `luna-native-catalog`) are told
   their context holds earlier calls and observations, which is wrong for the
   catalog layout.
6. **Statistics round integer ranges.** Reproduced: `1477147 to 1478146`
   prints as `1477000 to 1478000`. The old receipt showed exact bounds. This
   follows the specification's "4 significant digits", which was a mistake in
   the specification: integer bounds and counts should stay exact, and only
   non-integer statistics should round.
7. **Execute receipts grow and repeat.** From code, partly reproduced. Any
   operator in scope with flow lines (including `flow: contract` restatements,
   up to 2,000 characters each), ledger notes or adjustment notes gets a block,
   cached ones included, so earlier notes repeat on every later execute.
   Operators that did not run get a block and then appear again on a bare
   `not run:` line with no cause. A multi-line error's `at:`/`fix:` lines
   render as siblings of `result:` rather than under the error.
8. **The catalog never says `rolled back to task N` or `copied from task N`.**
   Reproduced. `taskLedger` is called without the task's changes
   (`dataflow-action-runtime.ts:588`), so a rollback appears as `updated` and
   its copies as `created`; `state-ledger.test.ts` asserts the wrong label.
9. **Task numbers disagree across receipts.** From code. The catalog numbers
   tasks as answered tasks + 1 + offset; sealed versions, rollback and
   `inspect state` use the raw turn index without the offset. After an
   unanswered turn, or with loaded state plus history, "task N" means different
   tasks in different receipts.
10. **Value rules.** Reproduced with the formatter: a newline inside Markdown
    text renders as `\\n`; a datetime without a timezone is read in the
    server's local zone (`2026-01-03T18:30:00` → `2026-01-04T02:30:00.000Z`);
    non-UTC offsets lose sub-millisecond digits. Only the `+00:00` case is
    tested.
11. **The `inspect graph` index quotes its cells.** Verified in code
    (`action-observations.ts:131`): every cell goes through the text quoting
    rule, so empty cells print `""` and task numbers `"1"`.

## Deviations from the specification

- Answer: `### 1. answer: ok` plus `Answer recorded.` instead of
  `answer: recorded`; the catalog heading is `### Catalog: task N` and `Task N
  sealed.` instead of `#### Task N` with a count line.
- Edit: `1 changes applied`; an edit made only of rollbacks reports 0 changes;
  the provenance heading is `Inputs from earlier state:`.
- Retrieve: refusals use `ACTION_FAILED` instead of `RESULT_STALE` /
  `RESULT_NOT_RUN`; captions put the annotation after the column count and omit
  `(columns requested)`, `cut at N characters` and `complete; statistics
  omitted`; loaded tables show `(scan, executed)` with `origin: loaded`.
- Skipped: `(earlier action failed)` instead of `(action N failed)`.
- Singular forms: `1 rows`, `1 operators in scope`.
- Catalog entries repeat the `columns:` line, unindented, before their records.
- Raw `info.error` text can still reach the model through `inspect state`
  with a view, and it may suggest `fork`, which is no longer a tool.

## The system prompt

- **Structure.** It is not the structure agreed on 2026-10-03 (role and
  grouped actions with editing and the catalog → working on a task with
  earlier tasks always present → examples for a single task, several tasks and
  earlier state). It is: role → concept glossary → actions → understanding
  observations → solving a task → optional multi-task sessions → operator and
  Python reference → examples. Earlier-task guidance is optional; the Examples
  section covers single tasks only; [system-prompt.md](system-prompt.md) and
  [calls-and-prompt.md](calls-and-prompt.md) were rewritten to call this
  structure approved.
- **Length.** Default 23.8k characters (21.0k before), with history and the
  catalog 29.4k, with data and flow statistics 30.0k.
- **Mismatches with the renderer.** Example captions, the partial-profile
  caption, singular shapes, missing `inputs:` lines and a promised `mean`
  that is never printed. Step 4 mentions flow statistics when they are off.
  `TOOLS.md` still says an answer must be the only action.
- **Fluency.** The context paragraph is repeated; edit atomicity and
  invalidation are explained three times; "described below only when they are
  enabled for this session" leaks assembly language; example headings mix
  `### Example:` and `### 1.`, the latter colliding with receipt headings.

## Test gaps

No test checks fence balance per settings combination, runs execute with
`flowEvidence` on and default views, checks the order of a complete sampled
table, checks `inspect graph` cell content, or renders with the zero-valued
format settings it stores. The "frozen receipt" tests re-render after
clearing workflow state that the renderer never reads, so they pass
trivially. Several tests assert the deviations above.

## Recommended order

1. Fix blockers 1–3, each with a failing test first; add a fence-balance and
   completeness check across all prompt setting combinations.
2. Decide the multi-task section at session start; restore the `versioned` and
   `session` context descriptions.
3. Keep integer statistics exact; fix catalog change labels and task
   numbering; stop repeating notes and flow contracts for cached operators.
4. Reconcile the prompt structure with the agreed one, and resolve the
   remaining deviations or update the specification deliberately.
5. Restore the submodule pointer, then rerun the validation on the final code
   with a case whose retrievals actually show statistics.
