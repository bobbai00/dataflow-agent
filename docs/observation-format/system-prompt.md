# System prompt

> Historical expression-mode prompt notes. The active prompt now follows four
> parts: role and objective, resources, working with Dataflows, and general
> examples. `buildRegisteredNativeSystemPrompt` renders
> [native-registered.md](../../agent-service/src/agent/prompts/native-registered.md).
> Read [the current generated prompt](../../native-mode/SYSTEM_PROMPT.txt) and
> [registered-Python design](../native-registered-python-design.md).

The native system prompt has three parts, in this order:

1. **Role and the dataflow tool.** The role and objective, then the actions
   with their effects, followed by everything the actions involve: editing the
   graph (commands, ports, invalidation), the operator catalog, Python inside
   operators, and how to read observations (operator blocks, records, data
   and flow statistics, errors and other diagnostics).
2. **Solving a task.** The five stages of an analysis, practical guidance on
   parsing, cleaning, reusing selections and answering from a table, and, in a
   multi-task session, how to work with earlier tasks.
3. **Examples.** A single task from preview to answer, then the examples that
   the session's settings call for.

The exact text for any configuration is generated by
`buildNativeModeSystemPrompt` in `agent-service/src/agent/prompts.ts` from the
template `prompts/native-mode.md` and its fragments. Three configurations are
rendered for reading, and a test keeps them in sync with the code:

- [default](../../native-mode/SYSTEM_PROMPT.txt): `sample_stats` and `full`
  views, no flow statistics, single task;
- [with flow statistics](../../native-mode/SYSTEM_PROMPT_WITH_EVIDENCE.txt);
- [with earlier tasks and historical state](../../native-mode/SYSTEM_PROMPT_WITH_STATE.txt).

## What each setting adds

The common text is the same in every session. Settings add sections and
examples; none changes the wording of another section.

| setting | adds to part 1 | adds to part 2 | adds examples |
|---|---|---|---|
| `sample_stats` in `retrievalViews` | Data statistics | — | data statistics: an aggregate's denominator; a partial profile |
| `flowEvidence` | Flow statistics | — | flow statistics: a cast that lost values; a join that dropped rows |
| `nativeChecks` | the `check` line | — | — |
| `multiTask` (or loaded state) | — | Earlier tasks in the session, including when to update an operator in place | building on an earlier task; revising a rule for the rest of the session |
| `stateHistory` | — | Saved versions: what answering a task saves, and how to read or restore it | comparing with an earlier task and going back |
| `stateLedger` | — | Task catalog and provenance | the catalog entry and provenance lines inside the multi-task example |
| `recall`, `resume`, `compact` tools | — | one paragraph each | — |

Whether a session has several tasks is decided when it starts, from the
`multiTask` setting or from state loaded before the first request. The prompt
does not change when a later request arrives, so the cached prefix stays valid
for the whole session.

## Examples are real receipts

Every receipt in the examples was produced by the live engine and renderer,
with data and flow statistics on and Markdown tables. When a session differs,
the builder removes what its receipts would not contain and converts the table
syntax: flow lines go when `flowEvidence` is off, statistics tables go when
`sample_stats` is not offered (and `records:` names the offered view), and
tables become tab-separated with `tableFormat: "tsv"`. Example calls use only
the views the session's tool schema offers. A test builds the prompt for every
combination of these settings and checks that each code fence closes, no
template marker remains, every example call validates, and the receipts carry
exactly the enabled statistics and table syntax.

## Size

Characters of the full prompt, including the 4.9k-character operator catalog:

| configuration | characters |
|---|---|
| no statistics views (`sample`, `full`) | 21,680 |
| default (`sample_stats`, `full`) | 27,895 |
| default with flow statistics | 34,454 |
| default with flow statistics, TSV tables | 34,168 |
| multi-task | 30,755 |
| multi-task with historical state | 35,117 |
| multi-task with historical state and catalog | 37,191 |
| every option | 43,848 |

The single-task example (about 3.7k characters) is the main addition over the
earlier prompt. The system prompt is the stable prefix of every request, so
after the first call of a session it is read from the provider's cache.
