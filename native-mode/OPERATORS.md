# Native mode: tools and operators

What the agent can call, what an operator is, and how a statement becomes an engine operator. The catalog table and the operator reference are generated from `agent-service/src/agent/native/catalog.ts`.

## Tools versus operators

The model sees one **tool**: `dataflow(edits, delete, observe)` (TOOLS.md). Operators are not tools. Every operator is one statement inside `edits`:

```python
id = operator(input_id, ..., parameter=value, ...)
```

- The left-hand **id** names the operator and its output table. Assigning to an existing name revises that operator in place and keeps its consumers. Names are Python identifiers that are not Python keywords and not operator names; each name is assigned once per program.
- **Positional arguments** are the ids of other operators, whose output tables are the inputs. The DAG edges are derived from them; there is no separate edge list.
- **Keyword arguments** are the operator's parameters. Types are bare names (`str`, `int64`, `float64`, `bool`, `datetime`); reducers and window functions are calls (`mean("x")`, `count()`, `lag("x", 1)`).
- **No nesting.** `limit(sort(t, by=["x"]), 1)` is refused; every intermediate table gets its own statement so it can be observed, revised and reported on.
- **Functions** are lambdas or `def`s written in the same `edits` and passed by name. Only `filter`, `map` and `process` take them; the function's return type is the contract (bool, dict, DataFrame).
- A program may hold many statements, in any order; the scheduler orders them by their inputs. A statement may reference tables from earlier calls.

## Operator reference (as it appears in the system prompt)

`T` stands for an input table; defaults are shown.

```text
T = scan(files, format="auto", skip_lines=0, header=True, names=None, all_text=False, delim=None, comment=None, widths=None, sheet=None, encoding=None, file_column=None, preview=None)
    Reads a file or glob (csv, tsv, txt, xlsx, html, json, parquet; format=lines/fwf/whitespace for non-delimited text) into a table. `preview=n` shows the first n RAW lines (or sheet rows) from `skip_lines` instead of parsing: use it on an unfamiliar file, then scan for real. Cells read as pandas.read_csv reads them: "NA", "N/A", "null", "nan" and the other pandas missing-value tokens are missing (the observation counts them) while "None" stays a value, as before pandas 2.0; a blank header is `Unnamed: <i>`, and a repeated header gets `.1`, `.2`. `all_text=True` keeps every cell as text, codes like 001 and those tokens included; `names` requires header=False and one name per column; `sheet` picks an Excel sheet or HTML table index; `file_column` records each row's source file. Example: `orders = scan("data/orders.csv")`.

T2 = project(T, keep=None, drop=None, rename=None)
    Keeps (in the given order) or drops the listed columns, then renames with a {old: new} mapping. At least one of the three. Rows are unchanged; a missing column or a name collision fails. Example: `trimmed = project(orders, keep=["region", "amount"], rename={"amount": "total"})`.

T2 = cast(T, column=dtype, ..., errors="raise")
    Changes column types: `cast(t, amount=float64, year=int64)`; a column whose name is not an identifier goes through `**{"Unit Price": float64}`. dtypes are str, int64, float64, bool, datetime; `datetime(format="%Y-%m-%d", tz="UTC")` takes an explicit format and timezone (naive values need tz). A value that does not convert fails the operator, or becomes missing with errors="null". Normalize text (thousands separators, percent signs) with map first.

T2 = filter(T, fn, doc="what the predicate keeps")
    Keeps the rows for which `fn(row)` returns True: `big = filter(orders, lambda row: row["amount"] is not None and row["amount"] > 100, doc="Keeps orders with an amount above 100")`. `row` is a read-only mapping of the input columns (`row["col"]`; a missing value is None). Return True to keep, False or None to drop; anything else, including a truthy string, is a contract error. Row order is preserved; the columns the function reads are measured, not declared. `doc` is one sentence stating the logical semantics of the predicate (which rows survive); it is shown with the results.

T2 = map(T, fn, doc="what the new row holds")
    Transforms every row: `fn(row)` returns the new row as a dict and those dicts are the output table: `priced = map(orders, lambda row: {**row, "unit_price": None if row["quantity"] in (None, 0) else row["amount"] / row["quantity"]}, doc="Adds unit_price = amount / quantity, None when quantity is missing or zero")`. `{**row, ...}` keeps the input columns; a dict without it keeps only the keys you return (rename or drop columns that way). One row out per row in, in the same order; every row must return the same keys; values are scalars or None; column types are inferred from the values (ints and floats mix to float64, one type per column otherwise). Missing values arrive as None; handle them explicitly. `doc` is one sentence stating the logical semantics of the function (which columns it adds, changes or drops, and how); it is shown with the results.

T2 = aggregate(T, by=[], name=reducer("col"), ..., dropna=True)
    One output row per distinct combination of the `by` columns (no `by` gives one row). As in pandas groupby, a row with a null in any `by` column belongs to no group and the observation counts those rows; dropna=False keeps null keys as their own group. Each other keyword is an output column: count() counts rows, count("col") non-null values, and count_distinct, sum, mean, min, max, median, stddev, first reduce a column. Reductions ignore nulls (first keeps them); an all-null sum is null; stddev is the sample standard deviation. Numeric reducers need numeric columns: cast first. Example: `by_region = aggregate(orders, by=["region"], total=sum("amount"), n=count())`.

T2 = join(L, R, on, how="inner", nulls_equal=False, suffix="_right", validate="many_to_many")
    Joins on explicit keys: `on="id"`, `on=["a", "b"]`, or `on=[("left_col", "right_col")]` when the names differ. how is inner, left, right, full, or cross (no keys). Null keys do not match unless nulls_equal=True. validate (one_to_one, one_to_many, many_to_one) fails the operator when the keys are not unique on the required side. Right-side columns that collide get `suffix`. No output order is promised: sort afterwards.

T2 = union(T1, T2, ..., schema="strict")
    Stacks two or more tables, keeping every row in input order. schema="strict" requires identical column names and types; "align" takes the union of columns in first-seen order and fills absent cells with null. Type mismatches need an explicit cast; nothing is deduplicated. Example: `all_orders = union(orders_2024, orders_2025, schema="strict")`.

T2 = distinct(T, columns=None, keep="first")
    Removes duplicate rows by the listed key columns (or the whole row). Missing values compare equal. keep decides which whole row survives; relative order is preserved. Example: `one_per_customer = distinct(orders, columns=["customer_id"], keep="first")`.

T2 = sort(T, by, nulls="last")
    Stable sort by one or more keys: by=["total"] ascending, or by=[("total", "desc"), "name"]. Ties keep their input order; nulls go last unless nulls="first". Example: `ranked = sort(by_region, by=[("total", "desc"), "region"])`.

T2 = limit(T, n, offset=0)
    Keeps n rows starting at offset, in the current order. Sort first for a meaningful top-k; past the end you get an empty table with the same columns. Example: `top_three = limit(ranked, 3)`.

T2 = window(T, partition_by=[], order_by=[...], name=fn, ...)
    Adds columns computed within partitions in the given order, then restores the input row order: `window(t, partition_by=["team"], order_by=["date"], prev=lag("score", 1), rank=dense_rank())`. Functions: lag(col, offset=1), lead(col, offset=1), row_number(), rank(), dense_rank(). row_number(), rank() and dense_rank() count from 1, as in SQL; pandas positions (cumcount(), a reset index) count from 0, so subtract 1 for those. Ties follow the order keys, so add a tie-break key when it matters. Null partition keys form one partition; null order values sort last.

T2 = unpivot(T, columns, name="variable", value="value")
    Wide to long: one output row per input row and listed column, keeping the other columns as keys and adding `name` (the column's name) and `value` (its value, nulls included). The listed columns need compatible types; cast first on mismatch. Example: `monthly = unpivot(wide, columns=["Jan", "Feb", "Mar"], name="month", value="rainfall")`.

T2 = pivot(T, index, columns, values)
    Long to wide: one row per distinct index combination, one column per distinct value of `columns`, cells from `values`. Each (index, columns) pair must occur once: aggregate first if combining is intended. Absent cells are null; null pivot keys fail. The output schema depends on the data: observe it before naming its columns downstream. Example: `wide = pivot(by_region_year, index=["region"], columns="year", values="total")`.

T2 = process(T1, ..., Tn, fn=function, doc="what it does")   or   process(fn=loader, doc="...")
    Table in, table out, in Python: `summary = process(orders, customers, fn=summarize, doc="Joins orders to customers and fits a linear trend per region")`. `fn` is a `def` from this program taking one pandas DataFrame per input table, in order (parameter names are yours), and returning one DataFrame with unique string column names, scalar cells and timezone-aware datetimes; with no input tables it takes no parameters and loads data itself. Each DataFrame arrives with its pandas row labels as the index, kept as pandas keeps them through filter, sort, distinct and head, so `full.loc[cleaned.index]` picks the cleaned rows of `full`; aggregate, join, union and pivot number their rows from 0. The index you return is kept the same way, and a named index, such as the keys of a groupby you did not reset, comes back as columns. `doc` is one sentence stating the logical semantics of the function (what the output table holds and how it is derived); it is shown with the results because nothing else about a process can be measured. Import packages inside the function. Use it for what no other operator expresses (custom parsers, binary formats, statistics, fitting, report layouts), not for filtering, deriving columns, grouping or joining.

T = parameters(weight=0.5, threshold=10, unit="fraction", ...)
    One row of named scalar parameters (numbers, strings, booleans or null). Pass this table to process alongside the data; read values with params.iloc[0]["weight"]. Reassign the same table to update dependent analyses. Use another parameter table for a temporary scenario. Store adjustable assumptions here instead of copying constants into several functions.

T2 = compare(A, B, keys=["col", ...])
    Row-level difference of two tables with the same meaning, such as two versions of a ranking, a cohort or a score table. Rows are matched on `keys` (default: the shared text and boolean columns; with no such column, by row position). The output has one row per matched or unmatched key with `in_a`, `in_b`, and for every other shared column `<col>_a`, `<col>_b` and, when numeric, `<col>_delta` = B minus A. Aggregate it for counts (rows in both, only in A, only in B, changed) or filter it for the rows that moved. Use it instead of writing a comparison function, so the two sides stay the exact tables they are.
```

## The three custom operators

| Operator | Function shape | Contract |
|---|---|---|
| `filter(T, fn, doc="...")` | `fn(row) -> bool` | drop-only: True keeps the row, False or None drops it |
| `map(T, fn, doc="...")` | `fn(row) -> dict` (the new row) | row-preserving: one dict per row, same keys in every row, column types inferred from the values; `{**row, ...}` keeps the input columns |
| `process(T1, ..., Tn, fn=f, doc="...")` | `f(df1, ..., dfn) -> DataFrame`; `f()` with no inputs is a loader | unknown: any rows, unique string column names, scalar cells, UTC datetimes |

Every custom operator carries a required `doc`: one sentence stating the logical semantics of the function (which rows a filter keeps, what row a map returns, what table a process produces). It is stored with the operator and leads the operator's flow guarantee in observed results, because nothing else about custom code can be measured.

`row` is a read-only mapping of the input columns; a missing value is None. The columns a function actually reads are measured at run time (`predicateColumns` for filter, `readColumns` and `columnDependencies` for map, where `{**row}` copies are not counted as reads) and drive the flow evidence and lineage, so nothing about the columns is declared.

## What an operator looks like end to end

Program statement:

```python
positive = filter(typed, lambda row: row["value"] is not None and row["value"] > 0, doc="Keeps rows with a positive value")
```

Normalized view stored on the operator (`nativeOp`):

```json
{ "type": "Filter", "inputs": ["typed"],
  "properties": { "func": "def apply(row):\n    return row[\"value\"] is not None and row[\"value\"] > 0", "entry": "apply", "doc": "Keeps rows with a positive value" },
  "revision": "<hash of type + inputs + properties>" }
```

Engine operator: one `DataProcessing` (or `DataLoading` for a source) whose code hands this JSON to the shared Python runtime (`agent-service/src/agent/native/python/runtime.py`), which validates the contract, runs it with pandas and records the counters that flow evidence reports (`Filter kept=135/1388`). The model never sees that code; it sees the statement it wrote.

## Errors

Every failure is one receipt line per operator: `[CODE; stage; revision] message`, then `Hint:`, `Field:` (the offending argument) and, for custom code, the failing line. `PROGRAM_SYNTAX` fails the statement that does not parse; `INVALID_ARGUMENTS` fails one statement; runtime codes (`MISSING_COLUMN`, `CAST_INVALID_VALUE`, `JOIN_CARDINALITY`, `UNION_TYPE`, ...) name the column, value or option; a consumer of a failed operator is told its upstream failed, a bystander that the run stopped elsewhere. The full taxonomy is in `docs/native-expression-mode.md` and `agent-service/benchmark/tests/test_native_error_taxonomy.py`.
